## 我与 GIS

地图只是空间世界的一种界面。我真正感兴趣的，是图层之下发生的一切：现实世界如何被抽象为坐标与数据，空间关系如何参与计算，以及这些结果最终怎样穿过系统，成为屏幕上的图形。

大学选择 GIS，是我把对地理与空间的好奇交给技术的开始。接触编程后，我第一次意识到，空间不只是被观察和描绘的对象，也可以被建模、计算，并转化为能够运行、交互和解决真实问题的系统。

我的开发经历从 WebGIS 起步，却没有停留在地图 API 的表层。沿着“一张地图是如何出现的”这个问题，我逐渐走向地图渲染、空间服务、数据处理与底层实现。比起让功能运行起来，我更愿意继续追问：数据为什么这样组织，坐标如何穿越不同参考系，空间计算如何保证正确，一次请求又如何最终成为屏幕上的像素。

从前端到服务端，从工具使用到底层原理，我正在建立属于自己的 GIS 认知体系。它不是一份技术名词清单，而是一条不断向下追问、又回到真实问题的路径。我希望获得的不只是完成需求的能力，更是理解空间、抽象问题并构建可靠系统的能力。

## 我怎样理解 GIS

GIS 的意义，从来不只是把地图放到屏幕上。它试图用数据描述现实，用计算理解关系，再把这种理解转化为能够支撑判断与行动的系统。

我理解的 GIS 能力，也不是记住多少工具和接口，而是能否读懂空间的语言，看清信息流动的链路，并知道每一个结果何以成立。

## 为什么写「图层深处」

知识如果只在任务发生时被调用，往往也会随着任务结束而散去。GIS 尤其如此：坐标、数据、算法、服务、渲染与业务彼此关联，却又散落在不同的项目、文档和工具之中。

写作迫使我停下来，把“做过”重新变成“理解”。我希望将项目中的实践、踩过的坑和对原理的追问连接起来，让零散经验逐渐形成一张属于自己的知识地图；也尝试把技术背后的“为什么”讲清楚，而不只是留下一个可以复制的答案。

因此有了「图层深处」。这里记录的不只是已经掌握的答案，也包括认知被修正、边界被拓宽的过程。每一次回望，既能看见自己走过的路径，也能发现下一层仍然值得追问的问题。
