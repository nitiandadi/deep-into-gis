# 地球模型与大地基准：经纬度和高程依附在哪个地球上

<p class="post-meta">2026-07-24 · GIS 核心概念 · 地球模型与大地基准 · 约 16 分钟</p>

上一章留下了一个问题：坐标必须依附于一套空间参考框架，那么描述地球位置时，这套框架究竟依附在哪个“地球”上？

最直觉的回答是“真实地球”。但真实地表有山脉、海沟、建筑和不断变化的海水，形状过于复杂，无法直接作为统一的坐标计算表面。

于是 GIS 和大地测量使用了一组层层抽象的地球：

```text
真实地表
→ 地球重力场形成的水准面
→ 规则、光滑的参考椭球
→ 与地球绑定的大地基准或参考框架
→ 经纬度、高程和空间直角坐标
```

这几个层次经常被统称为“坐标系”，但它们解决的是不同问题。理解它们之间的关系，才能真正解释为什么同样的经纬度可能落在不同位置，为什么 GNSS 高程不能直接当作海拔，以及为什么一个椭球名称不足以确定数据的空间基准。

## 我们面对的其实是多个地球表面

### 真实地表：对象实际所在的地方

真实地表是人、建筑、道路和山川所在的物理表面。它凹凸不平，并且持续变化：

- 地壳发生构造运动；
- 地面会因采矿、地下水开采和工程建设发生沉降；
- 海面受到潮汐、气压、洋流和温度影响；
- 建筑、道路和人工地形不断改变局部表面。

真实地表适合回答“对象实际在哪里”，却不适合直接承担全球统一的数学计算。我们不可能把每一座山和每一道海沟都写进经纬度定义。

### 大地水准面：由重力定义的物理参考面

如果海水只受重力和地球自转影响，静止海水表面会接近一个重力等位面。把这个表面向大陆下方延伸，可以得到大地水准面。

OGC 将大地水准面定义为：与重力方向垂直、并在局部、区域或全球范围内最佳拟合平均海平面的地球重力等位面。

它有两个重要特征：

1. 它由地球重力场决定，而不是由一个简单几何公式决定；
2. 铅垂线在每一点都与它垂直。

因为地球内部质量分布不均匀，大地水准面并不是规则椭球。它会在参考椭球上方或下方起伏。那些常见的“土豆形地球”图片通常夸张显示了这种重力场起伏，并不是按真实比例绘制的地球外形。

::: tip 大地水准面不是某一天的海面
真实海面会受潮汐、海流、风和气压影响。大地水准面是经过定义和建模的重力等位面，只是在物理意义上接近长期平均海平面。
:::

### 参考椭球：为了计算而建立的规则表面

大地水准面具有物理意义，但形状仍然太复杂。为了计算经纬度，人们再用一个旋转椭球去逼近地球。

把一个椭圆绕短轴旋转，就得到一个两极略扁、赤道略鼓的旋转椭球。描述它最常用的参数是：

- 长半轴 `a`：从椭球中心到赤道的距离；
- 短半轴 `b`：从椭球中心到极点的距离；
- 扁率 `f = (a - b) / a`；
- 工程资料中常写倒扁率 `1/f`。

只要给出 `a` 和 `f`，这个椭球的几何形状就确定了。

例如，WGS 84 参考椭球的长半轴是 `6378137 m`，倒扁率是 `298.257223563`；CGCS2000 参考椭球的长半轴同样是 `6378137 m`，倒扁率是 `298.257222101`。两者形状极其接近，但这并不意味着 WGS 84 与 CGCS2000 是同一个大地基准。

这正是最容易被忽略的一点：

> 椭球只定义形状和大小，不会自动说明它怎样放置在真实地球中。

## 球体、椭球体和大地水准面分别解决什么问题

| 模型 | 主要依据 | 优点 | 典型用途 |
|---|---|---|---|
| 球体 | 单一半径 | 公式简单、计算快 | 小比例尺展示、近似计算和教学 |
| 参考椭球 | 长半轴和扁率 | 规则、光滑，较好逼近地球整体形状 | 经纬度定义、大地测量和地图投影 |
| 大地水准面 | 地球重力场 | 具有物理高程意义 | 高程基准、海拔和重力相关计算 |
| 真实地表 | 实际地形和地物 | 最接近现实 | 测绘成果、DEM、点云和工程模型 |

它们不是互相竞争的四种答案，而是不同层次的模型。

球体可以看作对椭球的进一步简化；椭球为水平位置提供规则的几何参考；大地水准面为高程提供重力意义；真实地表上的点，则通过坐标和高程与这些参考面建立关系。

## 经纬度其实定义在椭球上

日常语言容易让人觉得，经纬度就是从地心向外看得到的两个角。但现代 GIS 中通常所说的纬度，是**大地纬度**或**椭球纬度**。

对椭球面上的一个点：

- 经度是该点所在子午面与本初子午面的夹角；
- 大地纬度是该点处椭球法线与赤道面的夹角；
- 椭球高是沿椭球法线，从椭球面量到目标点的距离。

这里的“椭球法线”非常关键。除赤道和两极等特殊位置外，它通常不会穿过椭球中心。因此，大地纬度和从地心直接连向该点形成的**地心纬度**不是同一个角。

```text
地心纬度：看“地心到点”的连线
大地纬度：看“椭球面法线”的方向
```

GIS、GNSS 和地图投影中常见的纬度一般是大地纬度。如果只说“纬度是点与地心连线和赤道面的夹角”，在球体模型中可以成立，在椭球模型中却会混淆两种纬度。

## 有了椭球，为什么还需要大地基准

想象我们做了一个大小准确的光滑椭球模型，但还没有把它套到地球上。它可以平移，可以旋转，也可以选择不同的方向作为零经线。此时椭球形状已经确定，但地球上的城市、控制点和卫星并不知道自己应该落在模型的哪里。

大地基准解决的就是“怎样把坐标系统锚定到地球”。

在现代术语中，**大地参考框架**比“大地基准”更准确；传统大地测量中仍广泛使用 datum，也就是“基准”。OGC 的概念模型把现代参考框架和传统大地基准放在同一类中处理。

一个大地基准或参考框架通常要回答：

- 原点在哪里；
- 三条轴怎样定向；
- 使用什么尺度；
- 采用哪个参考椭球；
- 通过哪些控制点、观测站或卫星轨道实现；
- 坐标是否随时间变化；
- 如果会变化，坐标对应哪个历元。

因此可以把关系理解为：

```text
参考椭球
= 一个有形状、有大小，但还没有落地的数学表面

大地基准或参考框架
= 规定这个数学空间怎样与地球绑定

地理坐标参考系统
= 大地参考框架 + 椭球坐标系统
```

上一章说 CRS 让数学坐标系统落到现实对象上。对于地理 CRS，这个“落地”的核心就是大地基准或参考框架。

## 参考系统和参考框架有什么区别

大地测量中还会区分 **Reference System** 和 **Reference Frame**。

- **参考系统**是一组理想定义和约定，例如原点、尺度、轴方向和时间演化规则；
- **参考框架**通过一组实际观测站的坐标、速度和观测成果，把理想系统实现出来。

可以把参考系统理解为建筑设计图，把参考框架理解为按照设计图实际建成、可以测量和使用的建筑。

国际地球参考系统 ITRS 规定了地心原点、尺度、方向及时间演化等原则；国际地球参考框架 ITRF 则通过全球观测站的三维坐标和速度实现它。随着观测数据更新，会形成 ITRF2000、ITRF2014、ITRF2020 等不同实现。

WGS 84 也不只是一个椭球。NGA 将它作为三维地心参考框架，并通过 GPS 监测站等设施实现。WGS 84 多次更新参考框架实现，但参考椭球的 `a` 和 `1/f` 可以保持不变。

这再次说明：**椭球参数相同或相近，不代表参考框架相同。**

## 传统局部基准和现代地心基准

### 传统局部基准

卫星大地测量普及之前，很难直接建立全球统一的地心坐标。传统方法通常选择一个适合本国或本地区的参考椭球，再通过地面控制点和天文观测把它定位、定向。

这类基准追求的是椭球在目标区域内较好贴合大地水准面。它可能在本地区表现很好，但椭球中心不一定与地球质心重合，也不适合直接支撑全球卫星定位。

1954 年北京坐标系和 1980 西安坐标系，都属于我国曾经使用的二维国家大地坐标系统。它们是在当时测量条件下建立的国家空间基准：

- 1954 年北京坐标系采用克拉索夫斯基椭球；
- 1980 西安坐标系采用 IAG 1975 椭球，并对我国国家大地网进行了重新处理。

“北京”和“西安”是坐标系统的历史名称，不表示所有坐标都从北京或西安市中心直接量起，也不能据名称猜测具体转换关系。

### 现代地心基准

GNSS 和空间大地测量要求坐标原点接近整个地球的质心，并建立全球一致的三维框架。这样的坐标可以直接服务卫星轨道、全球导航和跨区域测量。

CGCS2000 是全球地心坐标系统在我国的具体体现。我国自 2008 年 7 月 1 日起正式启用 CGCS2000，后续逐步完成原有国家大地坐标成果的转换。

WGS 84 则由美国国防部建立，广泛用于 GPS、导航和全球地理数据。

| 名称 | 基本性质 | 参考椭球 | 工程认识 |
|---|---|---|---|
| 1954 年北京坐标系 | 传统二维国家大地坐标系统 | 克拉索夫斯基椭球 | 历史存量数据仍可能出现 |
| 1980 西安坐标系 | 传统二维国家大地坐标系统 | IAG 1975 椭球 | 曾用于大量基础测绘成果 |
| CGCS2000 | 现代三维地心国家大地坐标系统 | CGCS2000 椭球 | 我国现行国家大地坐标系 |
| WGS 84 | 全球三维地心参考框架 | WGS 84 椭球 | GPS、导航和全球数据常用 |

这个表只描述概念层次，不能代替坐标转换方案。同一名称下面还可能存在不同实现、投影方式、分带、坐标历元和数据精度。

## 为什么 WGS 84 和 CGCS2000 不能简单画等号

在普通 Web 地图或米级应用中，WGS 84 与 CGCS2000 的坐标常常看起来非常接近，于是工程中容易出现一句话：“这两个可以直接当成一样。”

这种处理是否可接受，取决于业务精度、数据历元和参考框架实现。

它们都属于现代地心坐标系统，参考椭球形状也极其接近，所以在低精度场景中差异可能小到无法从屏幕上观察。但它们的定义、实现和维护体系并不相同。进入测绘、控制网、高精地图、形变监测或厘米级定位时，不能只看椭球参数，更不能把“肉眼能叠上”当作同一基准的证明。

正确的问题不是：

> 它们是不是一样？

而是：

> 在当前数据来源、坐标历元和精度要求下，忽略两套参考框架之间的差异会产生多大误差？

## 地球会动，坐标为什么还能固定

地球不是刚体。板块运动、地震、地面沉降和冰后回弹都会让地表点的位置随时间变化。

假设某个控制点每年相对全球地心框架移动几厘米。十年后，它在动态参考框架中的坐标就可能变化几十厘米。对于普通城市底图，这或许不明显；对于高精度测量、卫星定轨和形变监测，则无法忽略。

现代大地基准因此还要面对时间。

### 静态参考框架

静态框架通常与某个板块或区域一起运动，让区域内点的坐标在日常使用中近似保持不变。它便于国家和工程测绘维护稳定坐标，但相对全球框架仍可能随时间整体移动。

### 动态参考框架

动态框架允许点坐标随时间演化，参考站除了坐标，还可能带有速度。此时只写 CRS 名称还不够，还要说明**坐标历元**：这组坐标对应哪一个时刻。

可以用一个最简单的线性模型建立直觉：

```text
某时刻坐标
= 参考历元坐标
+ 点的速度 × 时间差
```

真实模型还可能包含地震位移、季节变化和其他形变改正，但底层认识已经很清楚：

> 高精度坐标不只有“在哪里”，还要有“什么时候在哪里”。

## 高程为什么比平面位置更容易混乱

当数据写成 `(经度, 纬度, 高程)` 时，第三个数看起来最直观，实际上往往最缺少定义。

### 椭球高：从参考椭球量起

GNSS 直接解算得到的通常是椭球高 `h`。它沿椭球法线，从参考椭球面量到目标点。

椭球高具有明确的几何意义，但参考椭球不是海平面，也不是重力等位面。一个位于海岸附近的点，椭球高不一定接近零。

### 正高：从大地水准面量起

正高 `H` 以大地水准面为零面，沿受重力方向影响的铅垂线度量。它更接近日常所说的“海拔”。

大地水准面相对参考椭球的起伏称为大地水准面高或大地水准面差距 `N`。常用关系是：

```text
h = H + N
```

也就是说，只有知道合适的大地水准面模型，才能把 GNSS 椭球高转换成对应高程基准下的正高。

### 正常高：我国测绘中常见的高程

我国国家测绘成果通常采用正常高系统，现行国家高程基准是 1985 国家高程基准。正常高不直接以大地水准面为参考，而是与似大地水准面相关。

如果正常高写作 `Hγ`，高程异常写作 `ζ`，则可建立类似关系：

```text
h = Hγ + ζ
```

因此，在国内工程中把 GNSS 椭球高转换为“85 高程”，需要的是与 CGCS2000 和 1985 国家高程基准相匹配的高程异常模型或可靠的区域拟合成果，不能随便减去一个固定常数。

::: warning “高程”必须带基准
椭球高、正高、正常高、地方假定高程和潮位基面高程可能同时出现在一个项目中。只保存一个名为 `elevation` 或 `z` 的字段，而不记录高程类型和基准，后续几乎一定会留下隐患。
:::

## 水平基准和高程基准是两套问题

CGCS2000、WGS 84、北京 54 和西安 80，主要出现在水平位置或三维几何参考的讨论中；1985 国家高程基准解决的是我国高程起算和传递问题。

一份工程数据完全可能同时使用：

```text
平面基准：CGCS2000
投影方式：某个高斯—克吕格投影带
高程基准：1985 国家高程基准
高程系统：正常高
```

这不是重复描述，而是分别回答：

- 平面位置怎样落到国家大地坐标框架；
- 经纬度怎样转换到工程使用的平面；
- 高度从哪个零面起算；
- 高度采用哪一种物理定义。

“EPSG 代码写了一个”也不一定覆盖全部垂直信息。许多常见数据格式和业务表只明确了二维 CRS，高程字段的参考系统仍要通过元数据、项目规范或复合 CRS 另行说明。

## 同样的经纬度为什么会落在不同位置

现在可以更准确地回答这个问题。

一组经纬度首先是在某个参考椭球上，按椭球坐标规则得到的角度；大地基准或参考框架再决定这个椭球怎样与真实地球绑定。

如果换了大地基准：

- 参考椭球的大小和形状可能变化；
- 椭球相对地球的原点和方向可能变化；
- 控制网或参考站的实现可能变化；
- 在动态框架中，坐标对应的时刻也可能变化。

所以，同一组经纬度数值放进不同基准，落到真实地球上的位置可能不同。同一个现实控制点转换到另一基准后，经纬度数值也会发生变化。

这不是地图软件的“偏移算法”，而是空间参考定义不同造成的必然结果。

## 为什么基准转换不能只找一组万能参数

从一个大地基准转换到另一个大地基准，通常需要建立两个参考框架之间的空间关系。

三维场景中常见的七参数包含：

- 三个方向的平移；
- 绕三条轴的旋转；
- 一个尺度差。

局部二维工程坐标中也常见四参数模型。但这些参数不是两个 CRS 名称之间天然附带的一组永恒常数。

参数可能依赖：

- 使用的重合控制点；
- 数据覆盖区域；
- 控制点质量和分布；
- 坐标历元；
- 转换模型和旋转约定；
- 目标精度；
- 是否还需要格网改正或高程模型。

因此，网上找到一组“北京 54 转 CGCS2000 七参数”，并不意味着它适用于全国，也不意味着它适用于当前项目。参数来源、适用范围、残差和检核点，比参数本身更重要。

具体的四参数、七参数、坐标转换和投影转换，将放到下一章展开。

## 工程中怎样检查大地基准和高程基准

拿到一份空间数据时，可以按下面的顺序检查。

### 水平位置

1. 使用的是哪个大地基准或参考框架？
2. 是地理坐标、地心坐标，还是已经投影的平面坐标？
3. 采用哪个参考椭球？
4. 如果是投影坐标，投影方法、中央经线和分带是什么？
5. 数据是否由其他基准转换而来？
6. 转换参数或格网来自哪里，适用范围和精度是多少？
7. 高精度数据是否记录坐标历元？

### 高程

1. `z` 是椭球高、正高、正常高，还是局部高度？
2. 使用哪个高程基准或零面？
3. 是否使用大地水准面或似大地水准面模型？
4. 高程模型与水平参考框架是否匹配？
5. GNSS、DEM、水准点和业务高程是否来自同一种高度系统？

### 验证

1. 用已知控制点检查转换前后的坐标；
2. 不只看屏幕叠加，还要计算残差；
3. 在数据覆盖范围内部和边缘分别布置检核点；
4. 记录 CRS、历元、参数来源、精度和处理链路；
5. 不用“差不多重合”代替测量意义上的正确。

## 回到“我们在哪个地球上”

现在可以把这一章压缩成四句话：

1. 真实地表是对象所在的物理世界，但它太复杂，不能直接作为统一计算面；
2. 大地水准面由重力场定义，提供高程的物理基础；
3. 参考椭球是规则的数学表面，用于定义经纬度和椭球高；
4. 大地基准或参考框架把数学坐标系统锚定到地球，并在现代高精度应用中处理时间演化。

因此，描述一个地理位置时，不能只说“经纬度是多少”，还要知道：

```text
在哪个参考椭球上
→ 属于哪个大地基准或参考框架
→ 坐标对应什么历元
→ 高程相对哪个参考面
```

第一章解决了“位置为什么需要坐标框架”，这一章解决了“坐标框架怎样落到地球”。但经纬度仍然位于曲面上，而地图、工程图和大量空间算法运行在平面中。

下一章进入 **地图投影与坐标转换**：曲面怎样展开到平面，投影转换、基准转换、四参数和七参数分别改变了什么。
