# 空间、位置与坐标：GIS 中的坐标到底在描述什么

<p class="post-meta">2026-07-24 · GIS 核心概念 · 空间与坐标 · 约 12 分钟</p>

看到下面三组数字时，你能判断它们分别位于哪里吗？

```text
116.397, 39.908
500000, 4420000
1200, 800
```

第一组很像经纬度，第二组很像以米为单位的投影坐标，第三组则可能是工程坐标、图片像素或游戏场景中的位置。但“很像”并不足以确定它们的含义。

`116.397` 是经度还是纬度？角度单位是度还是弧度？`500000` 从哪里开始测量？`1200, 800` 中的第二个数向上增长还是向下增长？如果这些信息都不知道，三个文件即使记录了完全相同的数字，也可能指向三个毫不相关的位置。

这正是理解 GIS 坐标的起点：

> 坐标不是位置本身，而是位置在某套空间参考框架下的数值表达。

## 现实世界中没有天然的坐标

一座建筑、一口水井和一辆行驶中的汽车，都真实地占据着某个位置。但建筑脚下没有天然刻着一对 `x, y`，地球表面也没有自然生成的经纬网。

经纬线、地图网格和工程坐标轴，都是人为了测量、记录和计算位置而建立的模型。现实位置进入 GIS，大致要经历这样一条抽象链路：

```text
现实中的对象
→ 选择要描述的空间
→ 建立参考框架
→ 按规则测量位置
→ 得到有顺序、有单位的坐标值
→ 存入文件、数据库或程序
```

计算机最终看到的只是数字。让这些数字具有空间意义的，是数字背后的规则。

这和描述一场会议的时间很相似。“9:00”只有放到某个日期、时区和计时规则中才完整。脱离这些条件，同一个 `9:00` 可以对应不同的真实时刻。坐标也一样：脱离参考框架的数字，不能唯一描述现实位置。

## 位置和坐标不是一回事

日常交流中，我们常把“位置”和“坐标”当作同义词，但在理解底层原理时，最好把它们分开。

- **位置**回答对象实际在哪里；
- **坐标**回答在选定的规则下，使用哪些数值来表达这个位置。

假设房间里有一个点 `P`。我们把左下角设为原点，向右为 `x` 轴正方向，向上为 `y` 轴正方向，单位使用米，测得：

```text
P = (8, 5)
```

现在把原点移动到原坐标中的 `(5, 2)`，坐标轴方向和单位保持不变。点 `P` 没有移动，但它在新框架中的坐标变成了：

```text
P = (3, 3)
```

如果再把单位从米改成厘米，坐标又会变成：

```text
P = (300, 300)
```

三个坐标描述的是同一个位置。改变的是表达位置的框架和数值，不是点本身。

反过来也成立。两个系统都保存了 `(8, 5)`，但如果它们的原点、轴方向或单位不同，这两个坐标就不一定指向同一个位置。

::: tip 两个容易混淆的事实
同一位置可以有多组坐标；相同的坐标值也可以表示不同位置。
:::

## 一组坐标为什么不能单独成立

一个可解释的坐标至少隐含了下面几类信息。

| 条件 | 它回答的问题 |
|---|---|
| 维度 | 使用一维、二维还是三维空间 |
| 原点 | 从哪里开始度量 |
| 坐标轴 | 沿哪些方向度量 |
| 轴顺序 | 数值依次对应哪条轴 |
| 单位 | 使用度、米、英尺还是像素 |
| 度量规则 | 怎样由坐标计算角度和距离 |
| 现实参照 | 这套数学框架怎样与地球、建筑或设备关联 |

在纯数学中，我们可以先定义一套坐标系，再讨论点的坐标。但 GIS 还要多解决一步：**这套数学坐标系怎样与地球或某个现实对象建立关系？**

OGC 的坐标参考标准把两个概念区分得很清楚：

- **坐标系统（Coordinate System，CS）**是一组规定如何把坐标赋给点的数学规则；
- **坐标参考系统（Coordinate Reference System，CRS）**通过基准或参考框架，把坐标系统关联到地球、建筑、图像或移动平台等对象。

可以先用一个简化关系理解：

```text
坐标系统
+ 与现实对象的参考关系
= 坐标参考系统
```

严格来说，地理 CRS、投影 CRS、工程 CRS 等类型的组成还会有所不同。这里先抓住最重要的一点：**坐标系统提供数学规则，坐标参考系统让规则落到现实世界。**

## 原点、坐标轴、单位和轴顺序

### 原点决定从哪里开始

房间坐标可以从某个墙角开始，建筑施工坐标可以从场地控制点开始，屏幕坐标通常从视口左上角开始。地心空间直角坐标则把原点放在地球质心附近。

如果不知道原点，`x = 100` 只表示“沿某条轴离原点 100 个单位”，却不知道这个位置实际上在哪里。

### 坐标轴决定朝哪里增长

数学课本中的二维坐标通常是 `x` 向右、`y` 向上；很多屏幕坐标却是 `x` 向右、`y` 向下；三维图形和设备坐标还可能采用不同的轴方向和左右手约定。

因此，一份坐标在地图上上下颠倒，不一定是数据内容错了，也可能是两个系统对轴方向的约定不同。

### 单位决定数字有多大

`1000` 可以是 1000 米、1000 英尺、1000 像素，也可以是一个角度量。数值相同，不代表尺度相同。

经纬度通常使用角度单位。度不是长度：同样一度经差，在不同纬度对应的地表距离不同。这也是为什么不能脱离具体空间模型，直接把经纬度当作普通平面坐标计算距离和面积。

### 轴顺序决定每个数是谁

坐标不是无序集合，而是一个有顺序的数值元组：

```text
(第一个轴的坐标, 第二个轴的坐标, 第三个轴的坐标……)
```

轴顺序在 GIS 工程里尤其容易出错。例如，EPSG 对 WGS 84 地理二维 CRS 的轴顺序定义为纬度、经度，而 GeoJSON 的位置数组使用经度、纬度。不同标准和软件接口可能采用不同约定，所以不能仅凭“大家平时都这么写”判断顺序。

::: warning 经度和纬度写反不是小问题
`(116, 39)` 与 `(39, 116)` 不是显示格式不同，而是在解释两组完全不同的位置。读取外部数据时，应同时确认 CRS、轴定义和具体格式的坐标顺序。
:::

## 从一维到三维：维度增加了什么

一维坐标只需要回答点在一条轴线上的位置。例如，道路里程桩可以用沿路线起点的距离描述。

二维坐标使用两个相互独立的数值描述平面或曲面上的位置。常见的地图平面坐标是 `(x, y)`，地理坐标则通常由纬度和经度构成。虽然它们都由两个数值组成，背后的几何空间和计算规则并不相同。

三维坐标增加第三个方向，但第三个数写成 `z`，不等于它天然就是“海拔”。它可能表示：

- 相对某个椭球面的高度；
- 相对某个高程基准面的高度；
- 局部空间中的竖直距离；
- 传感器或模型坐标中的第三条轴；
- 在只支持二维几何的流程中，被原样携带但没有参与计算的附加值。

因此，`(x, y, z)` 只能说明数据有三个坐标分量，不能单凭形式确定 `z` 的物理含义。

时间也经常与空间位置一起出现，例如车辆轨迹中的 `(x, y, z, t)`。但时间是另一种坐标维度，需要自己的原点、单位和参考规则，不能因为它排在第四位，就把它当作普通空间轴。

## GIS 中常见的五类坐标表达

同一个现实位置会在 GIS 链路中不断更换表达方式。

| 坐标表达 | 常见形式 | 主要用途 |
|---|---|---|
| 地理坐标 | 纬度、经度，可带椭球高 | 描述地球表面或附近的位置 |
| 投影坐标 | Easting、Northing，通常以米为单位 | 在平面上制图、量算和分析 |
| 地心空间直角坐标 | `X, Y, Z` | 大地测量、卫星定位和坐标转换 |
| 工程或局部坐标 | `x, y, z` | 建筑、矿区、厂区、车辆或设备局部空间 |
| 屏幕坐标 | 像素 `x, y` | 把地图结果绘制到显示设备 |

它们不是五种互不相关的数据，而是对位置的不同编码。

例如，用户点击地图上的一个像素时，程序可能经历：

```text
屏幕像素
→ 地图视图中的平面坐标
→ 地理坐标
→ 数据图层使用的坐标
→ 命中的真实空间对象
```

反过来，把一个水井画到屏幕上，也要把数据坐标逐层转换为当前地图和视口能够使用的数值。

这说明 GIS 不只是“存储带坐标的数据”，还要维护不同空间表达之间的关系。

## 同一位置为什么需要不同坐标

既然一个位置可以有多种表达，为什么不统一成一种坐标？

因为不同坐标表达服务于不同问题。

- 经纬度适合描述全球位置，却不适合直接套用普通平面公式完成所有量算；
- 投影坐标便于在特定区域内进行平面制图和计算，但会产生变形，也有适用范围；
- 地心坐标适合三维地球和大地测量，却不直观；
- 局部坐标可以让工程数值更小、方向更贴合场景，但离开局部参考关系就无法落到地球上；
- 屏幕坐标适合绘制和交互，却会随视图平移、缩放和旋转不断改变。

所以，坐标表达没有脱离场景的“最好”，只有是否适合当前计算。

## 工程中最常见的六种误解

### 1. 有坐标值，就等于有坐标系

一列 `x` 和一列 `y` 只是两个数值字段。除非知道它们的 CRS、单位、轴顺序和来源，否则不能可靠地与其他数据叠加。

### 2. 数值范围像经纬度，就一定是经纬度

局部坐标、归一化坐标和某些错误数据也可能落在经纬度的数值范围内。数值特征只能用于排查，不能替代元数据。

### 3. 给数据指定 CRS，就是完成坐标转换

指定 CRS 是声明“这些现有数值应该怎样解释”；坐标转换则会根据源、目标参考系统重新计算数值。把错误 CRS 强行写入数据，只会让错误获得一个看似完整的标签。

### 4. 能叠加显示，就说明坐标正确

小比例尺下的偏差可能不明显，底图或软件也可能在后台自动转换。显示接近只能证明结果看起来接近，不能证明基准、轴顺序、单位和转换过程正确。

### 5. 二维坐标加一个高程，就是完整三维位置

水平位置与高度可能依赖不同的参考面。如果不知道高度相对于什么测量，把它与经纬度拼成三个数，并不会自动形成严格的三维 CRS。

### 6. 坐标小数位越多，位置就越准确

小数位反映数值分辨能力，不等于测量精度。把误差数米的数据多保存几位小数，不会让它变成厘米级数据。

## 怎样完整地描述一个位置

当别人发来一组坐标时，不要只问“这是经纬度还是平面坐标”，至少还要继续问：

1. 使用什么坐标参考系统？
2. 坐标轴分别是什么，顺序如何？
3. 每条轴使用什么单位？
4. 数据是二维还是三维？
5. 如果有高度，它相对什么参考面？
6. 坐标是原始测量值，还是从其他 CRS 转换而来？
7. 数据覆盖什么区域，精度和时间条件是什么？

从数据层面看，可以把一个可解释的位置近似写成：

```text
有顺序的坐标值
+ 坐标轴和单位
+ 数学度量规则
+ 与现实对象的参考关系
= 可以解释和计算的位置
```

这也是空间数据与普通数值数据最本质的区别之一。坐标字段并不只存储“数”，它还依赖一整套外部语义。

## 回到最开始的三组数字

现在再看：

```text
116.397, 39.908
500000, 4420000
1200, 800
```

我们仍然不能直接断言它们位于哪里，但已经知道应该怎样追问：

- 数值对应哪些轴？
- 轴的顺序和方向是什么？
- 单位是什么？
- 原点在哪里？
- 使用什么 CRS？
- 这套参考关系怎样落到地球、局部场地或屏幕上？

只有这些信息补齐，数字才真正成为坐标，坐标才可以用于叠加、量算、分析和渲染。

这一章先建立了从现实位置到数值坐标的基本框架。但当参考对象扩大到整个地球，新的问题马上出现：地球究竟应该被抽象成球体、椭球体，还是一个起伏不平的重力等位面？经纬度和高程分别依附于什么表面？
