# 地图投影与坐标转换：曲面如何变成平面，坐标为什么会改变

<p class="post-meta">2026-07-25 · GIS 核心概念 · 地图投影与坐标转换 · 约 18 分钟</p>

前两章分别回答了两个问题：

1. 坐标为什么必须依附于一套空间参考框架；
2. 经纬度和高程究竟依附于哪个地球模型与大地基准。

但经纬度仍然位于椭球面上，而屏幕、纸张、工程图和大量空间算法都运行在平面中。于是我们还要解决两个不同的问题：

```text
问题一：怎样把椭球面上的经纬度映射到平面？
问题二：怎样让属于不同参考框架的坐标表达同一个现实位置？
```

第一个问题由**地图投影**解决，第二个问题通常涉及**基准或参考框架转换**。

工程中常把它们都笼统地称为“坐标转换”，于是很多错误也从这里开始：有人只修改 CRS 标签，有人把投影转换当成基准转换，有人拿一组来历不明的七参数套用整个项目，还有人看到两个图层能够叠加，就认为坐标处理已经正确。

这一章不从某个软件按钮开始，而是先建立一条完整的坐标操作链路。

## 地图投影不是把地球压平

### 曲面不能无损展开成平面

参考椭球是一个弯曲的二维表面，平面则没有曲率。两者的几何性质不同，因此不可能把整个椭球面连续地展开到平面，同时保持所有位置的长度、角度、面积和形状都不变。

可以把它类比为剥橘子皮：

- 不切开，橘子皮无法完整铺平；
- 切开后可以摊到桌面，但会出现拉伸、挤压或裂缝；
- 切得越细，局部越容易贴近平面，但整幅图也越不连续。

地图投影所做的不是消除变形，而是通过数学规则**安排变形**。

它建立的是一种从椭球坐标到平面坐标的映射：

```text
(经度 λ, 纬度 φ)
        ↓ 投影公式
(东坐标 E, 北坐标 N)
```

更抽象地写，就是：

```text
E = f(λ, φ)
N = g(λ, φ)
```

不同投影方法的区别，正体现在函数 `f`、`g` 怎样定义，以及它们选择优先保持什么性质。

### 投影变形具体改变了什么

地图投影可能产生四类基本变形：

- **长度变形**：地图上的一厘米在不同位置代表不同地面距离；
- **面积变形**：同样大小的地理区域在地图上显示成不同面积；
- **角度变形**：地面相交方向和地图上的夹角不再一致；
- **形状变形**：对象的局部轮廓被拉伸、压缩或扭曲。

一幅投影地图通常只能优先控制其中某些性质：

| 投影性质 | 优先保持什么 | 适合什么问题 | 仍然会失去什么 |
|---|---|---|---|
| 等角投影 | 局部角度与小范围形状 | 航向、地形图、工程制图 | 面积和距离仍会变化 |
| 等积投影 | 面积比例 | 土地、人口、资源统计 | 局部形状和角度可能变形 |
| 等距投影 | 某些指定方向或路径上的距离 | 距离表达、专题制图 | 不代表任意两点距离都准确 |
| 折中投影 | 让多类变形在视觉上较均衡 | 世界地图与综合展示 | 不严格保持角度、面积或距离 |

“等角”“等积”“等距”都不能脱离适用范围理解。等距投影并不是整张地图上任意两点的直线距离都等于真实地表距离；等角投影也不意味着一个大洲的整体形状完全不变。

地图投影的第一个工程原则因此是：

> 不要问哪种投影最好，而要问当前区域、尺度和业务最不能接受哪一种变形。

## 一个投影坐标参考系统由什么组成

OGC 将投影 CRS 定义为：通过地图投影这种坐标转换，从基础地理 CRS 派生出来，并使用笛卡尔坐标系统的 CRS。

可以先把它理解为：

```text
基础地理 CRS
+ 地图投影方法
+ 投影参数
+ 平面坐标轴与单位
= 投影 CRS
```

例如，一个完整的高斯—克吕格或横轴墨卡托投影不能只写“高斯投影”。至少还需要知道：

- 基础地理 CRS 和大地基准；
- 参考椭球；
- 投影方法；
- 中央经线；
- 纬度原点；
- 中央经线尺度因子；
- 假东距和假北距；
- 坐标轴方向与单位；
- 使用的分带规则和适用范围。

其中任何一项不同，都可能得到另一套平面坐标。

### 中央经线

中央经线是投影设计中的核心参考线。对于横轴墨卡托投影，离中央经线越远，通常越需要关注投影变形。

分带的目的就是把大范围区域拆成若干较窄区域，让每一带都围绕自己的中央经线展开，从而把变形控制在可接受范围内。

### 尺度因子

尺度因子描述投影后的微小长度与椭球面对应长度之间的比例关系。

如果中央经线尺度因子为 `1`，中央经线附近不施加额外缩放；如果小于 `1`，则会先在中央区域略微缩小，以便让带内其他位置的最大变形更加均衡。

尺度因子是局部量，会随位置变化。坐标单位写着“米”，不代表平面上任意一米都严格等于地面一米。

### 假东距和假北距

投影公式可能产生负坐标。为了方便记录和使用，可以在投影结果上增加固定偏移量：

```text
E = 原始投影横坐标 + 假东距
N = 原始投影纵坐标 + 假北距
```

“假”表示它们是人为加入的坐标偏移，不代表地球上真实存在一个向东或向北的物理距离。

只看 `500000` 这样的数值无法判断位置。它可能是某个投影带中央经线上的假东距，也可能是工程坐标、其他分带坐标或普通业务字段。

## 高斯—克吕格、横轴墨卡托和 UTM 是什么关系

### 横轴墨卡托

普通墨卡托投影把圆柱轴线与地轴方向一致，适合围绕赤道展开。横轴墨卡托可以理解为把圆柱方向“横过来”，让一条选定的经线成为主要参考线。

它是一种等角投影，局部角度和小范围形状保持较好，因此广泛用于地形图、工程测量和带状区域制图。

### 高斯—克吕格

高斯—克吕格投影属于横轴墨卡托体系的一种实现和使用传统。我国大量基础测绘和工程数据采用三度带或六度带高斯—克吕格投影。

但在工程中，仅知道“高斯投影”仍然不够。还必须确认：

- 使用三度带还是六度带；
- 带号怎样编码；
- 中央经线是多少；
- 横坐标是否包含带号；
- 假东距如何定义；
- 大地基准是北京 54、西安 80、CGCS2000，还是其他基准。

两个数据都叫“高斯投影”，不代表它们能够直接叠加。

### UTM

UTM 也是基于横轴墨卡托建立的分带投影系统。它把全球划分为 60 个经度带，每带通常宽 6°，并为各带规定中央经线、尺度因子和假坐标等参数。

UTM 的标准化程度较高，但使用时仍要确认：

- 带号；
- 北半球或南半球；
- 基础地理 CRS；
- 数据是否超出合理带宽；
- 跨带数据怎样处理。

高斯—克吕格与 UTM 使用相近的数学家族，不等于参数相同。即使中央经线相同，尺度因子、假坐标和坐标编码规则不同，结果也不会相同。

## Web Mercator 为什么适合显示，却不适合严肃量算

Web 地图最常见的 `EPSG:3857` 被称为 Web Mercator 或 WGS 84 / Pseudo-Mercator。

它流行的主要原因不是测量精度最高，而是非常适合全球在线地图的切片体系：

- 全球使用统一的平面坐标空间；
- 瓦片可以按规则分级和切分；
- 计算简单，客户端和服务端容易统一；
- 等角性质让局部方向和形状适合地图浏览。

但它会随着纬度升高迅速放大尺度和面积，无法表示极点，也不是严谨地基于椭球展开的普通墨卡托。EPSG 给它标注的用途就是 Web 制图和可视化，并明确指出它与椭球墨卡托之间存在尺度和北坐标差异。

因此：

- 用 `EPSG:3857` 做在线底图和瓦片显示通常合理；
- 用它直接做高精度距离、面积或工程测量通常不合理；
- “坐标单位是米”不能证明量算结果就是地面真实米数；
- 浏览器地图显示正常，不能替代业务分析对投影的选择。

实际项目中，可以让展示层使用 Web Mercator，同时在适合业务区域的投影 CRS、数据库地理类型或椭球算法中完成量算。

## “坐标转换”其实包含多种操作

日常开发中的“坐标转换”至少可能指下面几种完全不同的操作：

| 操作 | 数值是否变化 | 基准是否变化 | 例子 |
|---|---:|---:|---|
| 指定或声明 CRS | 否 | 否 | 告诉软件现有数字属于哪个 CRS |
| 轴顺序调整 | 是 | 否 | 从纬度、经度调整为经度、纬度 |
| 单位转换 | 是 | 否 | 弧度转度、英尺转米 |
| 投影或反投影 | 是 | 否 | 经纬度与高斯平面坐标互转 |
| 基准转换 | 是 | 是 | 北京 54、CGCS2000 等参考框架之间转换 |
| 高程转换 | 是 | 可能变化 | 椭球高与正常高或正高之间转换 |
| 局部工程转换 | 是 | 参考关系变化 | 国家坐标与矿区、厂区局部坐标互转 |

如果不先判断操作类型，就很容易用错误工具解决错误问题。

### 指定 CRS 不等于转换 CRS

假设一组数据本来是 `EPSG:4326` 经纬度：

```text
121.47, 31.23
```

如果直接把 CRS 标签改成 `EPSG:3857`，数值仍然是：

```text
121.47, 31.23
```

但软件会把它解释为距离伪墨卡托原点约一百多米的位置。真实位置没有被转换，只是数字被赋予了错误含义。

真正的坐标转换必须读取源 CRS，根据源与目标之间的操作重新计算坐标值。

```text
指定 CRS：这些数字原本是什么意思？
转换 CRS：同一位置在目标 CRS 中应该写成什么数字？
```

### 坐标转换操作在标准中怎样分类

OGC 对两个术语有严格区分：

- **Coordinate Conversion**：源 CRS 与目标 CRS 基于同一基准，参数由定义直接给定。地图投影、单位变化和轴顺序调整属于这一类；
- **Coordinate Transformation**：源 CRS 与目标 CRS 使用不同基准或参考框架，参数通常由观测和拟合得到，因此带有转换精度。

中文工程语境常把两者都叫“坐标转换”。名称可以简化，但思考过程不能简化：

> 这一步只是改变坐标表达，还是连坐标依附的参考框架也改变了？

## 从一个投影 CRS 到另一个投影 CRS，内部发生了什么

假设源数据位于旧基准下的高斯投影坐标，目标是新基准下的另一个投影坐标。完整操作通常不是一个公式，而是一条流水线：

```text
源投影坐标
→ 反投影为源地理坐标
→ 转为源地心空间直角坐标
→ 完成参考框架转换
→ 转回目标地理坐标
→ 正投影为目标平面坐标
→ 调整轴顺序和单位
```

其中每一步解决不同问题：

1. 反投影消除源平面表达；
2. 地理坐标转地心坐标，为三维基准转换提供计算空间；
3. 参考框架转换让坐标对齐到目标地球框架；
4. 目标投影生成业务需要的平面表达；
5. 轴顺序和单位转换满足目标 CRS 定义。

PROJ 的 pipeline 正是对这种串联坐标操作的实现。现代 GIS 软件看似只调用一次 `transform`，内部可能已经选择并执行了多步操作。

这也解释了为什么转换结果不能只由两个 EPSG 编码机械决定：同一对源、目标 CRS 之间可能存在多条候选路径，它们使用不同参数、格网、适用范围和精度。

## 四参数解决什么问题

工程中常说的二维四参数，通常指平面相似变换的四个参数：

- `ΔX`：横向平移；
- `ΔY`：纵向平移；
- `θ`：旋转角；
- `k`：尺度因子。

一种常见表达为：

```text
Xt = ΔX + k(Xs cosθ - Ys sinθ)
Yt = ΔY + k(Xs sinθ + Ys cosθ)
```

它能同时处理平移、旋转和统一尺度变化，并保持图形的角度与形状关系。

四参数常用于：

- 国家或城市平面坐标与施工坐标互转；
- 矿区、厂区和园区局部坐标对接；
- 两套局部平面控制网之间的配准；
- 小范围二维数据的工程转换。

四参数不能自动处理：

- 椭球和大地基准差异；
- 大范围区域中的非线性变形；
- 高程参考差异；
- 局部控制网中的复杂系统误差。

参数通常要用至少两个不重合的已知同名点求解。实际工程应使用更多、分布合理的控制点进行最小二乘估计，并保留独立检核点验证残差。

如果控制点只集中在场地一角，参数即使在拟合点附近表现很好，外推到另一侧也可能产生明显偏差。

## 七参数解决什么问题

七参数通常指三维 Helmert 转换中的：

- 三个平移参数：`Tx`、`Ty`、`Tz`；
- 三个旋转参数：`Rx`、`Ry`、`Rz`；
- 一个尺度参数：`s`。

它运行在地心空间直角坐标中，而不是直接对经纬度或普通平面坐标进行简单加减。

简化链路为：

```text
源经纬度和椭球高
→ 源地心坐标 X、Y、Z
→ 七参数 Helmert 转换
→ 目标地心坐标 X、Y、Z
→ 目标经纬度和椭球高
```

七参数适合描述两套三维参考框架之间整体性的平移、旋转和尺度差异。但它仍然只是一个全局或区域参数模型，无法自动吸收历史控制网中的局部扭曲。

### 旋转约定必须明确

七参数有两种常见旋转约定：

- Position Vector convention；
- Coordinate Frame convention。

两种约定对旋转参数的符号定义相反。同一组数字如果使用错误约定，结果就会发生偏差。

所以一组可使用的七参数不只是七个数，还必须同时说明：

- 源 CRS 与目标 CRS；
- 参数方向；
- 旋转约定；
- 平移、旋转和尺度单位；
- 参数适用区域；
- 参数求解历元；
- 转换精度和来源。

只从网络上复制“某坐标系转某坐标系七参数”，缺少这些元数据时，基本无法判断它是否适用于项目。

## 格网转换为什么往往比统一参数更精细

三参数或七参数用一组统一参数描述整个区域。它适合整体性差异，但历史大地网还可能存在随空间位置变化的局部变形。

格网转换会把区域内已知的坐标改正量存入规则格网。转换某个点时，根据周围格网节点插值得到该位置的改正量：

```text
点所在位置
→ 查找周围格网节点
→ 插值水平或垂直改正量
→ 应用到原坐标
```

它的优势是能够表达空间上不均匀的变形，代价则是：

- 依赖外部格网文件；
- 只能在格网覆盖范围内可靠使用；
- 必须确认格网对应的源、目标 CRS 和方向；
- 软件环境缺失格网时，可能退化为低精度转换或直接失败。

高精度坐标处理不能只记录“使用了 PROJ”或“调用了 GeoTools”。还应记录具体选择了哪条转换操作、是否加载了格网文件，以及软件报告的预期精度。

## 高程不能被顺便转换

很多二维转换接口会把第三个坐标原样带过去，让人误以为高度已经完成转换。

实际上，水平和垂直参考可能完全不同：

- 水平位置可能属于 CGCS2000；
- GNSS 给出的高度可能是椭球高；
- DEM 使用的可能是正常高；
- 工程项目还可能使用局部高程基准。

从椭球高转换到正高或正常高，需要匹配的大地水准面、似大地水准面或高程异常模型。只完成经纬度或平面坐标转换，不会自动改变高度的物理基准。

因此，三维数据处理要分别回答：

```text
水平坐标怎样转换？
垂直坐标怎样转换？
两者使用的参考框架、历元和模型是否兼容？
```

## 软件执行转换时，真正需要哪些信息

无论使用 GDAL、PROJ、GeoTools、PostGIS 还是其他 GIS 引擎，可靠转换至少需要：

1. 明确的源 CRS；
2. 明确的目标 CRS；
3. 数据所在区域；
4. 需要达到的精度；
5. 必要的坐标历元；
6. 可用的转换参数或格网；
7. 正确的轴顺序与单位。

### 使用 PROJ 检查候选操作

与其直接拼接一条简化 PROJ 字符串，更推荐先查询软件为源、目标 CRS 选择了什么操作：

```bash
projinfo -s EPSG:4326 -t EPSG:32650
```

`projinfo` 可以显示候选坐标操作、操作步骤、适用范围和精度信息。对于涉及基准转换的任务，还要检查输出中是否提示缺少格网，或者只提供 ballpark transformation。

所谓 ballpark transformation，通常只处理轴顺序、单位或本初子午线等差异，没有真正完成需要的基准改正。它可以帮助粗略显示，却不能冒充高精度转换。

### 使用 GDAL 转换矢量和栅格

矢量数据可以使用：

```bash
ogr2ogr \
  -s_srs EPSG:4326 \
  -t_srs EPSG:32650 \
  output.gpkg input.gpkg
```

栅格数据可以使用：

```bash
gdalwarp \
  -s_srs EPSG:4326 \
  -t_srs EPSG:32650 \
  input.tif output.tif
```

栅格重投影不仅改变坐标，还必须重新建立目标像元网格并进行重采样。最近邻、双线性和三次卷积等方法会对分类数据或连续数据产生不同影响。

因此，矢量坐标转换主要重新计算顶点；栅格重投影还会改变像元覆盖关系和像元值表达。两者不能只从命令参数表面理解为同一种处理。

### GeoTools 中不要忽略轴顺序

GeoTools 常见流程是读取源、目标 CRS，查找 `MathTransform`，再转换几何。工程中还经常使用 `CRS.decode(code, true)` 强制采用经度、纬度的 XY 顺序。

这里的 `true` 主要影响轴顺序解释，并不等于完成基准转换，也不能修复原始数据被错误标注 CRS 的问题。

无论使用哪种库，都应把下面三件事分开：

```text
解析 CRS 定义
→ 选择坐标操作
→ 对坐标或数据集执行操作
```

## 怎样为项目选择投影

选择投影可以按下面的顺序思考。

### 1. 数据覆盖多大区域

- 全球或洲际展示，需要关注整体视觉和全球连续性；
- 国家、省市尺度，需要选择适合区域和制图要求的投影；
- 工程场地可以使用合适分带投影或经过定义的局部工程 CRS；
- 狭长走廊、管线和道路还要考虑沿线变形分布。

### 2. 最重要的量是什么

- 方向和局部形状重要，优先考虑等角性质；
- 面积统计重要，优先考虑等积性质；
- 特定中心到各点距离重要，可以考虑相应等距投影；
- 只做互联网底图浏览，可以使用 Web Mercator；
- 工程放样和高精度量算，需要按照测绘规范、控制网和允许变形设计。

### 3. 区域是否跨带

跨投影带的数据如果分别保留在各带中，不便直接进行统一平面计算；如果强行放入某一带，远离中央经线的区域变形可能增大。

处理方式可能包括：

- 为整个业务区域选择更合适的统一投影；
- 分带处理，在结果层汇总；
- 在地理坐标或椭球模型上执行适合的算法；
- 为项目建立经过论证的局部投影或工程 CRS。

不能只因为某个带覆盖了项目中心，就默认它适合全部数据。

### 4. 是否有法规、标准或成果衔接要求

测绘、自然资源、工程建设和行业项目往往已有明确的坐标系统要求。技术上可行的投影不一定符合成果提交和数据交换规范。

选择投影不仅是数学问题，也受到既有控制网、历史数据、行业标准和协作系统约束。

## 坐标转换最常见的十个错误

### 1. 把修改 CRS 标签当成坐标转换

数值没有重新计算，只是改变了解释方式。

### 2. 只知道 EPSG 编码，不检查适用范围

编码可以唯一指向一个定义，但不保证这个定义适合当前区域和业务。

### 3. 把 WGS 84、CGCS2000 和 Web Mercator 当成同一类概念

前两者主要涉及大地参考框架，Web Mercator 是投影 CRS，概念层次不同。

### 4. 看到单位是米，就直接计算真实距离和面积

投影平面单位是米，不等于投影尺度处处为 1。

### 5. 忽略经纬度轴顺序

标准、文件格式和软件 API 可能分别采用纬度—经度或经度—纬度。

### 6. 忽略高程基准

二维转换成功，不代表第三维也正确。

### 7. 使用来历不明的四参数或七参数

参数没有方向、约定、区域、历元和精度信息，就很难安全使用。

### 8. 用少量且集中分布的控制点求参数

拟合点残差小，不代表整个项目范围都可靠。

### 9. 只在地图上目测叠加

小比例尺和自动重投影会隐藏误差，必须用独立控制点和数值残差检核。

### 10. 转换后丢失处理记录

结果数据如果没有保留源 CRS、目标 CRS、操作方法、参数来源和软件版本，后续很难复现和审计。

## 一套可落地的工程检查流程

拿到需要转换的数据时，可以按下面的顺序处理。

### 第一步：确认源数据

1. 原始坐标值是什么范围？
2. 源 CRS 是否来自可靠元数据，而不是靠数值猜测？
3. 轴顺序、单位和维度是什么？
4. 高程属于哪个垂直基准？
5. 数据是否带有坐标历元？

### 第二步：定义目标

1. 转换结果用于显示、分析、测量还是成果提交？
2. 目标区域和尺度是什么？
3. 允许误差是多少？
4. 是否必须遵循已有国家、行业或项目坐标规范？

### 第三步：选择操作

1. 是否只需要投影或反投影？
2. 是否涉及大地基准变化？
3. 应使用统一参数还是格网改正？
4. 是否需要处理高程和时间？
5. 软件选择的操作是否覆盖当前区域？

### 第四步：执行与验证

1. 保留原始数据，不覆盖唯一副本；
2. 使用双精度和可靠 GIS 引擎；
3. 用不参与参数求解的控制点检核；
4. 计算平面、垂直和三维残差；
5. 检查区域边缘和跨带位置；
6. 对栅格检查像元大小、范围和重采样方法；
7. 记录完整处理链路。

### 第五步：保存元数据

至少记录：

```text
源 CRS 与目标 CRS
→ 坐标操作名称和方向
→ 参数或格网文件
→ 坐标历元
→ 软件与版本
→ 适用范围和声明精度
→ 控制点与检核结果
```

## 回到“坐标为什么会改变”

现在可以把这一章压缩为五个结论：

1. 地图投影把椭球面坐标映射到平面，不可避免地重新分配长度、面积、角度和形状变形；
2. 投影 CRS 不只是一个投影名称，而是基础地理 CRS、投影方法、参数和平面坐标系统的组合；
3. 投影转换通常不改变大地基准，基准转换则会改变坐标依附的参考框架；
4. 四参数、七参数和格网转换解决不同层次的问题，参数必须带有方向、约定、范围和精度；
5. 坐标转换的正确性不能靠“看起来叠上了”判断，而要靠明确元数据、合理操作链和独立检核。

同一个现实位置在不同 CRS 中出现不同数值，并不是位置移动了，而是表达它的参考框架、坐标系统或映射规则发生了改变。

```text
现实位置不变
→ 参考框架可能变化
→ 曲面或平面表达变化
→ 坐标值重新计算
```

理解这条链路以后，再看到“转成 4326”“改成 3857”“套七参数”这样的说法，就应该继续追问：源和目标到底是什么？改变的是投影、基准、单位、轴顺序，还是高程？使用哪条坐标操作？误差又是多少？

前三章解决了位置、地球参考和坐标表达之间的关系。下一章将进入 **空间数据与几何模型**：点、线、面究竟是什么，Geometry、Feature、Layer 和 Dataset 又怎样组织现实世界。
