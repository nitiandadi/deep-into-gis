# 理解空间索引：为什么地图查询可以很快

<p class="post-meta">2026-07-14 · GIS 全链路 · 空间算法</p>

当数据量从几百条增长到几百万条，逐条判断空间关系会迅速变得不可接受。空间索引解决的核心问题，是在执行精确计算前，先排除绝大多数不可能命中的对象。

## 从一个地图框选开始

用户在地图上拖出一个矩形，系统需要返回范围内的要素。最直观的做法是遍历所有几何对象，但它的计算成本会随数据量线性增长。

空间索引通常先比较对象的最小外接矩形（MBR），得到一批候选集，再执行精确的几何关系判断。

```ts
const candidates = spatialIndex.search(viewportBounds)
const result = candidates.filter(feature => intersects(feature, viewport))
```

## 为什么常见的是 R-Tree

R-Tree 会把相近对象的边界框组织在同一个层级节点中。查询时，只访问与目标区域相交的分支，因此能跳过大量无关数据。

::: tip 两阶段查询
先用边界框做粗过滤，再用真实几何做精确判断，是空间查询中非常常见的模式。
:::
